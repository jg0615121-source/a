# 내가 직접 한다 (hands-on-pc)

사용자는 비개발자이고 "니가 할 수 있으면 니가 해라"를 여러 번 분명히 말했다.
**사용자에게 일을 넘기는 것은 마지막 수단이다.** 아래 순서를 건너뛰고 "이거 눌러 주세요"라고 쓰면 규칙 위반이다.

## 0. 넘기기 전 점검 (매번)
1. API·CLI로 되는가? (gh/MCP, Vercel API, 프로젝트 스크립트) → 되면 그걸로 끝낸다.
2. 사용자 PC가 연결돼 있는가? `mcp__Remote_Desktop_Commander__list_devices` (Online 확인)
3. 연결돼 있으면 **아래 절차로 화면을 직접 조작한다.** 확인 질문 없이 바로.
4. 정말 막힐 때만(2단계 인증 코드, 결제, 본인만 아는 비밀번호) 사용자에게 넘긴다. 그때도 "무엇을, 어디서, 몇 번 누르는지"를 한 줄로, 이미 그 화면을 띄워 둔 채로.

## 1. 화면 조작 절차 (Windows PC)
도우미 스크립트 `scripts/pc.ps1`을 PC에 한 번 올려 두고(`C:\Users\Public\pc.ps1`) 점 소싱해서 쓴다.

```powershell
. C:\Users\Public\pc.ps1
Shot "C:\Users\Public\s.jpg" 1280            # 화면 찍기 (JPG, 축소) → read_file로 본다
Find-Window "Vercel"                          # 제목에 단어가 든 창 찾기 (크롬·엣지 둘 다 확인)
Front 28288                                   # 그 창을 앞으로 (프로세스 Id)
Click 663 279 "Deployment Protection"         # 앞 창 제목에 단어가 있을 때만 클릭
Paste "문구" "Deployment Protection"           # 클립보드 붙여넣기 (한글 IME와 무관)
Pixel 672 279                                 # 스위치 색 등 상태 확인
```

규칙
- **키·클릭을 보내기 전마다 앞 창 제목을 확인한다**(`Click`/`Paste`가 자동으로 한다). 사용자가 다른 창(게임, Claude 앱)을 보고 있으면 입력이 엉뚱한 곳에 들어간다. 실제로 Claude 앱에 주소가 전송된 사고가 있었다.
- 좌표는 원본 해상도 기준이다. 축소 스크린샷에서 읽은 좌표는 배율을 곱한다(1280 폭이면 ×1.5).
- 누른 뒤에는 반드시 다시 찍어서 결과를 확인한다. 확인 창이 뜨면 그 창도 처리한다.
- 페이지가 어느 브라우저에 열렸는지 모르면 `Find-Window`로 찾는다(이번엔 크롬이 아니라 엣지였다).
- 사용자가 게임 중이면 사용자가 "해"라고 한 경우에만 앞으로 가져온다. 아니면 끝날 때까지 기다리되, 기다리는 동안 할 수 있는 다른 일을 한다.
- 웹 결과는 PC에서 `curl.exe -s -o NUL -w "%{http_code}"`로 확인한다(이 컨테이너에서 막힌 주소도 PC에선 열린다).

## 2. 보안
- 토큰·비밀번호를 화면이나 대화에 출력하지 않는다. 필요한 경우 PowerShell 변수로만 다룬다.
- 결제, 계정 삭제, 공개 범위를 넓히는 일은 사용자가 그 일을 시킨 경우에만 한다.
